# Bug Report: BH-RC-001 — Cart State Desync Under Concurrent User Load

**Reporter:** Michael R. Smith  
**Date Found:** 2025-01-15  
**Severity:** High  
**Priority:** P1  
**Status:** Open  
**Environment:** SauceDemo v1.x | Chrome 120 | Playwright 1.44 | 4 parallel workers

---

## Summary

When 4 concurrent browser sessions add the same product to the cart simultaneously, the cart badge counter intermittently shows `0`, `null`, or fails to update within the expected 5-second window on 1 out of 4 sessions. This indicates a potential client-side state management race condition in the cart reducer.

---

## Steps to Reproduce

1. Open 4 browser contexts simultaneously (Playwright `browser.newContext()` × 4)
2. Log in as `standard_user` in all 4 contexts concurrently
3. Navigate to `/inventory.html` in all 4 contexts
4. Click `[data-test^="add-to-cart"]` (first item) in all 4 contexts simultaneously using `Promise.all`
5. Read the `.shopping_cart_badge` text in each context within 5 seconds

```
npm run test:race
```

---

## Expected Result

All 4 sessions should show cart badge = `"1"` after adding one item.

---

## Actual Result

| Session | Cart Badge |
|---------|-----------|
| User-1  | `"1"` ✅  |
| User-2  | `"1"` ✅  |
| User-3  | `null` ❌  |
| User-4  | `"1"` ✅  |

Session 3 failed to display the cart badge within the 5-second timeout on 2 out of 5 test runs.

---

---

## Root Cause Hypothesis

The cart state is managed client-side in the SPA's local storage / Redux-like store. Under parallel load, the cart update event listener may not flush synchronously when multiple click events fire within the same JavaScript event loop tick. This is consistent with a missing `await` on the cart update dispatch or a missing debounce guard on rapid DOM events.

---

## Impact

- **User Impact:** Customer adds item to cart but badge doesn't update → assumes add failed → clicks again → duplicate item in cart → frustration and potential lost order
- **Business Impact:** Cart abandonment rate increases; potential duplicate charges if backend does not deduplicate
- **Severity:** High — affects core purchase flow

---

## Suggested Fix

1. Add a loading/disabled state to the Add to Cart button immediately on click (prevents double-dispatch)
2. Ensure cart state reducer is wrapped in a synchronous atomic operation
3. Add E2E retry assertion: `await expect(badge).toHaveText('1', { timeout: 10_000 })` to catch flaky updates in CI
